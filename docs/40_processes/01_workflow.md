# タスク遂行ワークフロー

AI エージェントがタスク（Notion の TSK-N など）に取り組む際の標準手順。原典の詳細は [specs/03_workflow.md](../specs/03_workflow.md)。

## 前提

- 作業開始前に [AGENTS.md](../../AGENTS.md) と [10_architecture/07_coding-rules.md](../10_architecture/07_coding-rules.md) を参照する。
- 既存ルールと矛盾する場合は `docs/` を正とする。
- 明示の許可がない限り破壊的 Git 操作（force push, reset --hard, branch -D 等）は行わない。

## 7 フェーズ

**1〜4 はユーザーと AI の議論**、**5 は AI 単独作業**、**6〜7 はユーザー検品と後片付け**。1〜4 で成果物のカタチを十分に詰め、5 を AI が自律的に完遂できるようにするのが設計思想。

| # | フェーズ | 主体 | 成果物 |
| - | -------- | ---- | ------ |
| 1 | 課題提示 | ユーザー | Notion 課題シート |
| 2 | 課題共有 | ユーザー + AI | 内容が確定した課題シート |
| 3 | 設計議論 | ユーザー + AI | 設計ドキュメント（判断ログ含む） |
| 4 | 実装議論 | ユーザー + AI | 設計ドキュメント末尾に「実装計画」 |
| 5 | 実装作業 | AI | コミット済み作業ブランチ + 自主レビュー |
| 6 | 評価 | ユーザー | マージ済み PR |
| 7 | 後処理 | AI | 「完了」ステータスの Notion タスク |

各フェーズ末尾に**出口判定**があり、AI が「次フェーズへ進んでよいか」を明示的に確認する。

## 各フェーズの要点

- **Phase 1 課題提示**: ユーザーが Notion タスクテンプレート（一行サマリ / 背景・動機 / 完了条件 / スコープ外 / 制約 / 関連資料 / 不明点）で課題を作成。AI はステータスを「進行中」に更新。
- **Phase 2 課題共有**: AI が課題を取得・パースし、空欄・矛盾・曖昧点を質問。完了条件が測定可能か等をチェックして出口判定。課題シートは Phase 2 完了時点でフリーズし、以降の更新は `docs/` 側に書く。
- **Phase 3 設計議論**: 論点を抽出し、各論点で複数案（A/B/C）をメリデメ付きで議論。方針確定後、設計ドキュメントに**判断理由を併記**して書き起こす。
- **Phase 4 実装議論**: 設計ドキュメント末尾に実装計画（変更ファイル・手順）を追記。
- **Phase 5 実装作業**: 作業ブランチで実装。ビルド（`cd backend && pnpm build` / `cd frontend && pnpm build`）を通し、自主レビューしてコミット。
- **Phase 6 評価**: ユーザーが PR レビュー・マージ。
- **Phase 7 後処理**: Notion タスクを「完了」に更新。
