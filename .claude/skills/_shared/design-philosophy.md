# 設計思想（skill-workflow / skill-project-planning 共通）

両スキルが共有する基本思想。各 SKILL.md からここを参照する（重複記述を避ける）。

## 議論を厚く → 実行契約 → 自走（効率の連鎖）

1. **議論フェーズを厚くする** → 成果物（設計書・プロジェクトDoc）を「曖昧さゼロの実行契約」まで詰める。
2. **その契約を後続（サブエージェント / 個別タスク）へ渡す** → 文脈を持たない初見の AI でも完走できる。
3. **後続は背後で対話不可（コールドスタート・質問不可）** → 契約に無い判断はできない → **実装中の確認が自動的にゼロになる**。

「実装中の確認を減らす」は、契約を完全にすることで達成される。実装中に聞くのではなく、聞く必要をなくす。

## 出口判定

各フェーズの末尾で AI が **出口判定** を行い、ユーザーへ「次フェーズへ進んでよいか」を明示的に確認する。
判定はチェックリストに照らして行う（各スキルの `references/` 参照）。

## 前提（必ず最初に確認）

1. [AGENTS.md](../../../AGENTS.md) と [docs/specs/00_rules.md](../../../docs/specs/00_rules.md)（および関連 `docs/`）を参照する。
   本ファイルと `docs/` が矛盾した場合は **`docs/` を正とする**。
2. 破壊的 Git 操作（`git push --force` / `git reset --hard` / `git branch -D` 等）は
   ユーザーの明示許可なしに行わない。
3. Notion・PR 等の**外向き操作**は、各スキルの出口判定でユーザー承認を得てから実行する。

参照: [askuserquestion-policy.md](askuserquestion-policy.md) / [notion-refs.md](notion-refs.md)
