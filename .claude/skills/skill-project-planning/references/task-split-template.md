# タスク分割の原則と出口判定（skill-project-planning）

## タスク切りの原則

- 1 タスク = skill-workflow に単独で渡せる自己完結単位（**1 PR で完結する規模**を目安）。
- 大きすぎる成果物は複数 TSK に分割。小さすぎる雑多な作業はまとめる。
- タスク間の依存は最小化し、依存がある場合は順序を明記。
- 完了条件はタスク単位でユーザー視点・測定可能に。

## 各タスク候補で決める項目

- 名前（TSK タイトル。動詞で始める例: 「〜を実装する」「〜を設計する」）
- 一行サマリ / 完了条件（測定可能に）
- 重要度（HIGH / MIDDLE / LOW）
- 規模感（S=些細 / M=1〜2 ファイル / L=通常。skill-workflow 圧縮ルールの判定材料）
- 依存・順序（先行タスク）

## 出口判定（チケット作成前・必須確認）

> 「タスク分割案が揃いました。N 件のタスクに分割します: [一覧]。この内容で TSK チケットを作成してよろしいですか？」

承認後、`notion-create-pages` でタスク DB（ID は [_shared/notion-refs.md](../../_shared/notion-refs.md)）に各 TSK を作成:

- **プロパティ**: 名前 / ステータス=「未着手」 / 重要度 / 規模（S/M/L） / 完了予定日（あれば） / **プロジェクト リレーション = この PRJ**
- **本文**: タスクテンプレートの見出しを埋める。少なくとも一行サマリ・完了条件・関連資料（プロジェクトページへのリンク）は記入。
- スプリントは指定がない限り空のまま。

作成後、**採番された TSK-N の一覧（URL 付き）をユーザーへ報告**し、依存・推奨着手順を添える。
