# Petal プロジェクト計画ワークフロー（3 フェーズ）

Notion「プロジェクト」DB の案件を、実行可能な TSK チケット群に落とすまでの**上流**手順。
個々のタスクの設計・実装は本スキルの範囲外で、[skill-workflow](../skill-workflow/SKILL.md)（7 フェーズ）が引き継ぐ。

```
[本スキル] PRJ-N 要件 → 議論 → プロジェクトDoc → TSK-1, TSK-2, ... 作成
                                                      ↓ 各タスクごとに
[skill-workflow] TSK-N: 課題共有 → 設計 → 実装議論 → 実装 → 評価 → 後処理
```

## 設計思想（skill-workflow と共通）

- **Phase 1〜2 はユーザーと AI の議論** → プロジェクトの成果物（作業・創作・システム要件）を曖昧さゼロまで詰める
- **Phase 3 はタスク分割** → 各 TSK が skill-workflow に単独で渡せる粒度・自己完結性を持つように切る
- 方針確認は可能な限り **AskUserQuestion ツールで構造化**し、ユーザーの判断負荷を「読んで返信」から「選ぶ」に下げる
- 各フェーズ末尾で AI が **出口判定** を行い、次フェーズへ進んでよいか明示的に確認する（必須確認は Phase 2 / 3）

## フェーズ進行表

| # | フェーズ | 主体 | 入力 | 成果物 | 出口判定 |
| --- | --- | --- | --- | --- | --- |
| 1 | 要件提示 | ユーザー | （ユーザー指示） | Notion プロジェクトページ（要求記述） | ユーザー指示で完了 |
| 2 | 要件議論 | ユーザー + AI | プロジェクトページ | 整備済みプロジェクトドキュメント | **必須確認** |
| 3 | タスク分割 | AI 主体 + ユーザー確認 | プロジェクトDoc | TSK チケット群（プロジェクト紐付け済み） | **必須確認**（作成前） |

## 前提（必ず最初に確認）

1. [AGENTS.md](../../../AGENTS.md) と `docs/` の関連ドキュメントを参照する。
2. Notion への書き込み（ページ作成・更新）は**外向き操作**。チケットの一括作成は Phase 3 の出口判定でユーザー承認を得てから実行する。

## 実行手順

### Phase 1: 要件提示

ユーザーが「プロジェクト」DB に新規プロジェクトを作成し、要求（やりたいこと・解決したい問題・創りたいもの）を記述して「PRJ-N を計画する」等の指示を出す。

AI は指示を受けたら:
1. `notion-fetch` でプロジェクトページを取得
2. `notion-update-page` でステータスを **「進行中」** に更新
3. Phase 2 へ移行

### Phase 2: 要件議論（必須確認）

#### AI のアクション
1. プロジェクトページの記述をパースし、**何を作る/解決するプロジェクトか**を自分の言葉で要約して確認
2. 空欄・曖昧・矛盾を抽出し、**論点ごとに AskUserQuestion で議論**:
   - 目的・背景（なぜ今やるか）
   - 成果物の分類 — **作業内容 / 創作内容 / システム要件** のどれが含まれるか、各々の中身
   - スコープ（対象・対象外）
   - 制約（技術・運用・期日・予算等）
   - 完了条件（プロジェクト全体として「これが揃えば完了」と言える状態）
3. 必要に応じて `docs/` の既存設計・要求を読み、整合性を確認
4. 確定内容を**プロジェクトページ本文へ反映**（口頭合意のまま放置しない）

#### プロジェクトドキュメントの推奨構成（プロジェクトページ本文）
一行サマリ / 背景・目的 / 要求（ユーザー記述の整理） / 成果物（作業内容・創作内容・システム要件） / スコープ（対象・対象外） / 制約 / 完了条件 / 関連資料 / 未確定事項
（テンプレート提案は本ファイル末尾「テンプレート改善提案」を参照）

#### 出口判定（ユーザー確認）
> 「要件議論フェーズの成果物が揃いました。このプロジェクトは: [サマリ 5-10 行]。タスク分割フェーズに進んでよろしいですか？」

チェック:
- 一行サマリが具体的
- 成果物（作業 / 創作 / システム要件）の中身が列挙されている
- スコープ外・制約が明示（「なし」明記でも可）
- 完了条件が**測定可能**
- 未確定事項がすべて解決済み、または「タスク化時に確定」と明記

### Phase 3: タスク分割（必須確認 → チケット作成）

#### AI のアクション
1. プロジェクトドキュメントの成果物・完了条件を、**実行可能な単位**に分解
2. 各タスク候補について次を決める:
   - 名前（TSK タイトル。動詞で始める例: 「〜を実装する」「〜を設計する」）
   - 一行サマリ / 完了条件（測定可能に）
   - 重要度（HIGH / MIDDLE / LOW）
   - 規模感（typo・1〜2 ファイル・通常 のどれ相当か。skill-workflow の圧縮ルール判定材料）
   - 依存・順序（先行タスク）
3. **分割案を一覧で提示し、AskUserQuestion / 表で承認を得る**（粒度・抜け漏れ・順序をレビューしてもらう）

#### タスク切りの原則
- 1 タスク = skill-workflow に単独で渡せる自己完結単位（1 PR で完結する規模を目安）
- 大きすぎる成果物は複数 TSK に分割。小さすぎる雑多な作業はまとめる
- タスク間の依存は最小化し、依存がある場合は順序を明記
- 完了条件はタスク単位でユーザー視点・測定可能に

#### 出口判定（チケット作成前・必須確認）
> 「タスク分割案が揃いました。N 件のタスクに分割します: [一覧]。この内容で TSK チケットを作成してよろしいですか？」

承認後、`notion-create-pages` でタスク DB（`collection://3539ca7d-99dc-808f-833e-000b24ce030c`）に各 TSK を作成:
- **プロパティ**: 名前 / ステータス=「未着手」 / 重要度 / 規模（S/M/L） / 完了予定日（あれば） / **プロジェクト リレーション = この PRJ**
- **本文**: タスクテンプレートの見出し（一行サマリ / 背景・動機 / 完了条件 / スコープ外 / 制約 / 関連資料 / 不明点・迷い）を埋める。少なくとも一行サマリ・完了条件・関連資料（プロジェクトページへのリンク）は記入
- スプリントは指定がない限り空のままにする（テンプレ既定の固定スプリント紐付けに注意）

作成後、**採番された TSK-N の一覧（URL 付き）をユーザーへ報告**し、依存・推奨着手順を添える。

### 後処理（プロジェクト完了時）

各 TSK が skill-workflow で完了し、プロジェクトの完了条件をすべて満たしたら、AI は `notion-update-page` でプロジェクトのステータスを **「完了」** に更新する。

## skill-workflow への引き継ぎ

本スキルの成果物（TSK チケット）はそのまま skill-workflow の Phase 1 入力になる。
ユーザーが個別タスクで「TSK-N に取り組む」と指示したら [skill-workflow](../skill-workflow/SKILL.md) を起動する。

## Notion テンプレート / プロパティ（適用済み）

本スキル導入時に以下を Notion へ反映済み。

- **プロジェクト DB**:
  - 既定テンプレ本文を Phase 2 の議論成果を受ける構成へ刷新（一行サマリ / 背景・目的 / 要求 / 成果物〔作業・創作・システム要件〕/ スコープ / 制約 / 完了条件 / 関連資料 / タスク分割 / 未確定事項）。
  - `種別`（select: システム開発 / 創作 / 調査 / 運用）プロパティを追加。Phase 2 で設定する。
  - 既定テンプレ「新規プロジェクト」1 つに統一済み（旧構成の重複テンプレは削除済み）。
- **タスク DB**:
  - 本文テンプレは skill-workflow Phase 1 と一致（一行サマリ / 背景・動機 / 完了条件 / スコープ外 / 制約 / 関連資料 / 不明点・迷い）。
  - `規模`（select: S=些細 / M=1〜2 ファイル / L=通常）プロパティを追加。skill-workflow の圧縮ルール判定材料。Phase 3 で設定する。
  - 既定テンプレの固定スプリント紐付けを解除済み（新規タスクはスプリント未割当で作成される）。
