# Petal プロジェクト計画ワークフロー（3 フェーズ）

Notion「プロジェクト」DB の案件を、実行可能な TSK チケット群に落とすまでの**上流**手順。
個々のタスクの設計・実装は本スキルの範囲外で、[skill-workflow](../skill-workflow/SKILL.md)（7 フェーズ）が引き継ぐ。

```text
[本スキル] PRJ-N 要件 → 議論 → プロジェクトDoc → TSK-1, TSK-2, ... 作成
                                                      ↓ 各タスクごとに
[skill-workflow] TSK-N: 課題共有 → 設計 → 実装議論 → 実装 → 評価 → 後処理
```

## 設計思想（要点）

- **Phase 1〜2 はユーザーと AI の議論** → プロジェクトの成果物（作業・創作・システム要件）を曖昧さゼロまで詰める。
- **Phase 3 はタスク分割** → 各 TSK が skill-workflow に単独で渡せる粒度・自己完結性を持つように切る。
- 各フェーズ末尾で**出口判定**（必須確認は Phase 2 / 3）。詳細は [_shared/design-philosophy.md](../_shared/design-philosophy.md)。

## フェーズ進行表

| # | フェーズ | 主体 | 入力 | 成果物 | 出口判定 |
| --- | --- | --- | --- | --- | --- |
| 1 | 要件提示 | ユーザー | （ユーザー指示） | Notion プロジェクトページ（要求記述） | ユーザー指示で完了 |
| 2 | 要件議論 | ユーザー + AI | プロジェクトページ | 整備済みプロジェクトドキュメント | **必須確認** |
| 3 | タスク分割 | AI 主体 + ユーザー確認 | プロジェクトDoc | TSK チケット群（プロジェクト紐付け済み） | **必須確認**（作成前） |

## 実行手順

### Phase 1: 要件提示

ユーザーが「プロジェクト」DB に新規プロジェクトを作成し、要求を記述して「PRJ-N を計画する」等の指示を出す。
AI は `notion-fetch` でページ取得 → `notion-update-page` でステータスを**「進行中」**に更新 → Phase 2 へ。

### Phase 2: 要件議論（必須確認）

1. プロジェクトページをパースし、**何を作る/解決するプロジェクトか**を自分の言葉で要約して確認。
2. 空欄・曖昧・矛盾を抽出し、**論点ごとに AskUserQuestion で議論**:
   - 目的・背景（なぜ今やるか）
   - 成果物の分類 — **作業内容 / 創作内容 / システム要件** のどれが含まれ、各々の中身は何か
   - スコープ（対象・対象外）/ 制約（技術・運用・期日・予算等）
   - 完了条件（プロジェクト全体として「これが揃えば完了」と言える状態）
3. **既存実装の有無を必ず確認**（省略不可）。成果物に「〜を新設/実装する」が含まれる場合、着手前に
   `docs/20_features/`・`docs/` 目次・`backend/src/<feature>/`・`frontend/` を調べ、**既に実装済みでないか**を確かめる。
   既存なら成果物・スコープ・完了条件をその実態に合わせて縮小し、未確定事項に明記する。
   （根拠: PRJ-18 で「音声ライブラリ新設」を前提に計画したが、実際は TSK-117〜120 で実装済みだった取りこぼし。
   この確認を欠くと重複タスクを生む。）
4. 必要に応じ `docs/` の既存設計・要求を読み整合性を確認。
5. 確定内容を**プロジェクトページ本文へ反映**（口頭合意のまま放置しない）。

#### プロジェクトドキュメントの推奨構成

一行サマリ / 背景・目的 / 要求（ユーザー記述の整理）/ 成果物（作業内容・創作内容・システム要件）/ スコープ（対象・対象外）/ 制約 / 完了条件 / 関連資料 / 未確定事項。
（プロパティ・テンプレ定義は [_shared/notion-refs.md](../_shared/notion-refs.md)）

#### 出口判定（ユーザー確認）

> 「要件議論フェーズの成果物が揃いました。このプロジェクトは: [サマリ 5-10 行]。タスク分割フェーズに進んでよろしいですか？」

チェック: 一行サマリが具体的 / 成果物（作業・創作・システム要件）の中身が列挙 / **「新設/実装する」成果物は既存実装の有無を確認済み** / スコープ外・制約が明示 / 完了条件が**測定可能** / 未確定事項がすべて解決済み、または「タスク化時に確定」と明記。

### Phase 3: タスク分割（必須確認 → チケット作成）

1. プロジェクトドキュメントの成果物・完了条件を**実行可能な単位**に分解。
2. 各タスク候補の項目を決める（名前・サマリ・完了条件・重要度・規模・依存）。
3. **分割案を一覧で提示し承認を得る**（粒度・抜け漏れ・順序をレビュー）。
4. 承認後にチケット作成。原則・項目・作成手順・出口判定はすべて
   [references/task-split-template.md](references/task-split-template.md) に従う。

## skill-workflow への引き継ぎ

本スキルの成果物（TSK チケット）はそのまま skill-workflow の Phase 1 入力になる。
ユーザーが個別タスクで「TSK-N に取り組む」と指示したら [skill-workflow](../skill-workflow/SKILL.md) を起動する。

## 後処理（プロジェクト完了時）

各 TSK が skill-workflow で完了し、プロジェクトの完了条件をすべて満たしたら、
`notion-update-page` でプロジェクトのステータスを**「完了」**に更新する。
