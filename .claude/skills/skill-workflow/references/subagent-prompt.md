# Phase 5 サブエージェント起動テンプレ

Phase 4 の設計書を**実行契約**として、worktree 上のサブエージェントにバックグラウンド実装させる。
サブエージェントは**コールドスタート・背後で対話不可**。渡せるのは設計書とこのプロンプトのみ。

## 起動手順（メインスレッドの AI）

1. `Agent` ツールを **`isolation: "worktree"`** + **`run_in_background: true`** で起動
   （専用 worktree が自動生成され、メインの作業ツリーは汚れない）。
2. プロンプトに**必ず**含める:
   - 設計書のパス（最初に通読させる）
   - 対象タスクブランチ名
   - 実装計画の作業順序・各コミットの完了確認方法
   - 完了条件（下記）
   - **中断条件**（= 想定外時の「中断要相談」。該当時は質問せず停止し最終報告に記録）
   - 自主レビュー観点（[self-review.md](self-review.md)）
3. 起動後、ユーザーへ「バックグラウンドで実装を開始しました。完了通知が来たらレビューします」と伝えて解放。
4. **小規模タスク**（圧縮ルールの typo / 1〜2 ファイル）はサブエージェント起動が見合わないためメインで直接実装してよい。

## サブエージェントのアクション

1. 実装計画通りにコミットを積む。
2. 各コミットで完了確認実行（型チェック / ビルド / lint / 手動シナリオ）。
3. 「中断条件」に該当したら**質問せず停止し、状況を最終報告に記録して終了**。
4. lint 後は必ず **`git status` で未コミット自動修正を確認**。
5. コミットメッセージは**日本語**（[AGENTS.md](../../../../AGENTS.md) §2）。
6. 完了条件:
   - `bash .claude/skills/skill-workflow/scripts/verify.sh all` が通る
     （backend build / frontend build / docs markdownlint をまとめて検証）
   - 設計書の完了条件をすべて満たす
   - 必要な migration が `backend/database/migrations/` に追加され、ローカル適用可能
   - `.env.example` 更新（必要時）
7. 自主レビュー実施（修正があれば追加コミット）。

## 完了通知後（メインスレッドの AI）

1. サブエージェントの成果物（コミット・差分）と最終報告をレビュー。
2. 完了条件・[自主レビュー観点](self-review.md)の充足を確認。不足あれば追加指示 or 自分で修正コミット。
3. 問題なければ Phase 6 へ。
4. **中断して終了していた場合**: 最終報告をユーザーへ共有して相談 → 設計書を更新 → 更新後の設計書を実行契約として再度サブエージェント起動。
